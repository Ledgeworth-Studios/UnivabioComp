# W6-2 — The one-page description, and a script that refuses to let it be two

**Status:** DONE
**Files touched:** `docs/one-pager.md` (new), `docs/one-pager.pdf` (new),
`tools/build_one_pager.py` (new), `justfile`, `README.md`, `BACKLOG.md`

## What I did

`docs/one-pager.pdf` is the submission one-pager: the problem, what this does
differently, why the three-valued verdict is the whole idea, two things found in
real registry data, what is built and what is blocked, and what it is built with.

**The words are not in the PDF. They are in `docs/one-pager.md`**, and
`just one-pager` renders them. That is the important decision here — see below.

It fills about eighty-five per cent of an A4 page, in the same colours as the
interface, so the printed page and the running app look like the same project.

## Why I did it this way

**A PDF you cannot edit without the tool that made it is a dead end.** The human
entrant will want to reword this the night before submitting — that is what
everybody does with a one-pager. If the only artefact were a binary, that edit
means recreating the whole thing in something else and losing the layout. So the
prose is a Markdown file that can be read, edited and reviewed in a diff, and the
PDF is a rendering of it. Change a sentence, run one command, commit both.

**The script counts the pages of the finished file and fails if there is more
than one.** "One page" is the entire brief, and it is exactly the sort of
requirement that silently stops being true when somebody adds a sentence. So the
build re-opens the PDF it just wrote, counts the pages in it, and exits non-zero
with a message naming the file to cut words from.

**I checked that guard actually fires**, rather than trusting it — the lesson
from the contrast test earlier in this run, which passed every assertion while
measuring an empty string. I appended sixty sentences of filler, ran it, and got:

```
ERROR: the brief is one page and this is 2. Cut words from docs/one-pager.md
       — do not shrink the type below 8pt.
exit=1
```

Then restored the file and confirmed it went back to one page and exit 0. The
guard works, and I know it works because I watched it fail.

That message deliberately says *cut words*, not *shrink the type*. The obvious
way to fix a one-pager that has become two pages is to drop the font size, and
the result is a page nobody can read. The instruction is in the error where
somebody will actually meet it.

**reportlab is not a dependency of this project.** The product has no reason to
know how to make a PDF. `just one-pager` pulls the library in for the length of
that one command with `uv run --with reportlab`; `pyproject.toml` is untouched
and the container image is unaffected.

**Type sizes were chosen by rendering and looking.** The first version was set
too small and left forty per cent of the page empty, which reads as though there
was not much to say. I enlarged it and re-rendered until it filled the sheet. The
page-count guard is what makes that safe to do by eye — overshoot and the build
fails rather than quietly producing two pages.

**Every claim on it is one the tool can support.** The 91-site trial, the health
centres study `NCT06251323`, the 248 tests, "no API key required" — each of those
was verified during the task that built it, and the two blocked model steps are
stated as blocked rather than described as though they exist.
