# D-1 — Every push now runs the same checks a build agent has to run

**Status:** DONE
**Files touched:** `.github/workflows/check.yml`, `BACKLOG.md`

## What I did

Added continuous integration. Every push to this repository now runs `just check`
— the linter, the formatting check, and the whole test suite — on GitHub's
machines, and the result shows up as a green tick or a red cross next to the
commit.

Verified, not assumed: the workflow ran on the commit that added it, finished
green, and its log shows the real steps executing —
`ruff check` passed, 23 files already formatted, 79 tests passed.
[Run 32447886479](https://github.com/Ledgeworth-Studios/UnivabioComp/actions/runs/32447886479).

## Why I did it this way

**Because this project's safety net had a hole in it.** `docs/decisions/0001`
decided to push after every single task, on the reasoning that the remote is the
backup — work that exists only on this laptop has already been lost once. That
reasoning is right, but a backup nobody inspects can happily hold broken code. CI
closes that: the remote is now not just a copy, it is a *checked* copy.

**The CI job runs `just check` and nothing else.** It would have been easy to
write out the three commands separately in the workflow file. I didn't, because
then there would be two lists — the one in the `justfile` that agents run locally
and the one in the YAML that CI runs — and they would drift. Whatever `just
check` means today, CI means the same thing. If a future task adds a step to
`check`, CI picks it up for free.

**No secrets are configured on this workflow, deliberately.** The test suite makes
no network calls — `tests/conftest.py` fails loudly if any test tries — so it
needs no API key. That is worth keeping true: the day CI needs a secret is the day
a fork's pull request can no longer be checked safely.

**Standard, boring actions.** `actions/checkout`, `astral-sh/setup-uv`,
`extractions/setup-just`. Nothing custom, nothing to explain to a judge beyond
"install the tools, install the project, run the checks".

## What the next run should know

- **A red tick on GitHub is now real information.** Before you start a task, it is
  worth a glance at `gh run list --limit 3`. If the last run is red, the tree you
  are about to build on is broken, and finding that out now costs seconds.
- CI is free here — the repository is public, so standard runners are unlimited.
  There is no reason to skip a push to save minutes, and `CLAUDE.md` already says
  so.
- The workflow also triggers on `pull_request` and can be run by hand from the
  Actions tab (`workflow_dispatch`), though nothing uses either of those yet.
