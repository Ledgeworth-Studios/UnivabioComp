# W1-4 — Cutting the eligibility blob into criteria we can quote

**Status:** DONE
**Files touched:** `whynot/criteria.py`, `tests/test_criteria.py`, `BACKLOG.md`

## What I did

ClinicalTrials.gov does not store eligibility criteria as a list. It stores them
as **one text field** containing whatever the study team typed into a box. There
is no per-criterion identifier, no structure, no guarantee of formatting. Before
anything can judge a person against a criterion, something has to cut that blob
into individual criteria — and it has to do it without changing a single
character, because the product's promise is that every reason it gives you quotes
the registry verbatim.

`whynot/criteria.py` does that. Each criterion comes back with four things: its
position, whether it is an inclusion or an exclusion, a cleaned-up readable
version, and `source_text` — an exact slice of the original blob.

The most important test in the file asserts that for all seventeen recorded
trials, every `source_text` is found character-for-character inside the original
registry text. If a future change ever starts paraphrasing, that test goes red.

### What the real data actually looks like

I dumped all seventeen recorded blobs and read them before writing any code.
Every one of the following is real:

- Normal case: `Inclusion Criteria:` / `Exclusion Criteria:` headers with `*`
  bullets.
- **The header itself written as a bullet, in capitals**: `* INCLUSION
  CRITERIA:` (NCT06096870). A splitter that looks for bullets first turns the
  header into a criterion.
- **Four headers, not two.** NCT01271491 studies cases and controls, so it has
  `Inclusion Criteria, cases:`, `Exclusion Criteria, cases:`, `Inclusion Criteria,
  controls:`, `Exclusion Criteria, controls:` — the section has to be able to
  switch back.
- **Markdown-escaped numbering**: `1\.` instead of `1.` (NCT06737159).
- **Markdown-escaped punctuation everywhere**: `Testosterone \>100 ng/dL`,
  `m\^2`, `\[HBV\]`. Shown to a user unprocessed, those backslashes look broken.
- **Roman-numeral and lettered sub-items**: `i)`, `ii)`, `iii)` (NCT06408259),
  and one bullet written as `\-`.
- **No headers at all.** NCT00132080 opens straight into bullets.
- A bullet with no space after it: `--Measured or calculated creatinine
  clearance…`.

### The one rule that matters most

Indented sub-bullets are folded into the criterion above them, never emitted on
their own. NCT06096870 says:

```
* Participants must have adequate organ and marrow function as defined below:

  * Absolute neutrophil count (ANC) >=1,500/microliter
  * Platelets >=100,000/microliter
  ...
```

"Platelets >=100,000/microliter" as a standalone criterion is nonsense — you
cannot judge anyone against it, and quoting it to a user tells them nothing.
Folded into its parent it is a normal lab-values requirement. Top-level bullets
start new criteria; indented ones extend the current one. There is a test that
checks the folding happened *and* that "Platelets" never appears as a criterion
of its own.

### Unclassified is a real answer

When a blob has no headers, the criteria come back tagged `UNCLASSIFIED` rather
than being guessed into one bucket or the other. That mirrors the `UNKNOWN`
verdict: not knowing is reported, not hidden. Mistagging an exclusion as an
inclusion would invert its meaning, which is the worst possible failure here.

79 tests pass.

## Why I did it this way

**No model.** It would have been easy to hand the blob to Claude and ask for a
JSON list. `docs/PLAN.md` restricts the model to *judging* criteria, and this is
why: a model asked to split text will occasionally tidy a sentence while
splitting it, and a tidied sentence is no longer a verbatim quote. The whole
traceability promise rests on the split being mechanical. It is also instant and
free, and it runs identically every time.

**Character offsets rather than string surgery.** The splitter records where each
criterion starts and ends in the original blob, then slices. That is what makes
"the source text is verbatim" true by construction rather than by careful
discipline — there is no code path that can rewrite the source text, because the
source text is never built, only sliced.

**Never raise.** A blob we cannot make sense of degrades to one big criterion,
not to an exception. A crash here would drop a trial out of someone's results
without telling them, which is exactly the silent failure this project is
supposed to be the opposite of.

**A lead-in sentence is dropped, not kept.** "Children eligible for the trial
must fulfil all of the following criteria:" introduces criteria; it is not one.
The rule is mechanical — a non-bulleted line ending in a colon that appears
before the first bullet of a section.

## What the next run should know

- **The splitter is good, not perfect, and the imperfections are known.** Two
  worth naming, both caused by the registry's own formatting rather than by the
  code:
  - NCT06737159 contains the literal text `* Crackles and/or wheezing. 2. Aged 5
    weeks - 24 months old.` — the study team glued item 2 onto the end of a
    bullet. It comes out as one criterion containing both. No splitter can fix
    that without editing the source text, which we will not do.
  - NCT06408259 indents `i)` but not `ii)` and `iii)`, so the first becomes part
    of its parent criterion and the other two become separate criteria. Both
    readings are judgeable, so it is harmless, but don't be surprised by it.
- **The counts in `test_real_records_of_differing_shape_split_as_expected` are
  the regression net.** If you change the splitting rules, expect that test to
  move. Re-read the affected blob and decide whether the new number is better
  before updating it — do not just paste in whatever the code now produces.
- **W1-5 is next, and it is the go/no-go.** It has everything it needs now: real
  trials (`whynot/registry.py`), a person (`whynot/profile.py`), the structured
  fields already decided (`whynot/hardfilter.py`), and criteria split with exact
  quotes (this module). The backlog is explicit that if the three-valued verdicts
  come back incoherent, the honest move is to mark W1-5 `BLOCKED` and say so —
  not to spend hours tuning prompts. That instruction is worth re-reading before
  starting, because the temptation will be strong.
- W1-5 will be the first task in the project that needs an API key. There is no
  `.env` in this repo and there must never be one committed — `.gitignore`
