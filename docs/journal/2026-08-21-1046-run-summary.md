## The four things worth telling the human about

**1. The interface was making a false promise, and I found it by checking.**
The footer said *"Nothing you type here is stored or sent anywhere else."* Both
halves were untrue: the condition and location go to ClinicalTrials.gov, and the
server was writing every registry response and a timestamp to disk — from which
what somebody searched for is plain. Fourteen such rows were on this machine. The
cache is now off by default and the interface says three true things instead of
one false one (`docs/decisions/0005`).

**2. A latent bug would have told the parents of premature babies the wrong
thing.** `NCT01066728` states its age bounds as "27 Weeks to 32 Weeks", and those
are weeks *of pregnancy*, not weeks of life. Read as ages since birth, a
two-week-old fell outside them and the code said `NOT_MET` — the exact error
`docs/PLAN.md` weights above all others. It now answers `UNKNOWN` and says to ask
the study team which they mean. The general rule that came out of it is the more
valuable half: **a `NOT_MET` requires that no reasonable reading of the registry's
wording admits the person** (`docs/decisions/0006`).

**3. Some things could not be done here, and are not pretended otherwise.** The
`Dockerfile` is written and **has never been built** — Docker runs on this machine
but cannot reach Docker Hub. That is `W5-5c`, `BLOCKED`, with the exact error
recorded. Publishing to a public URL (`W5-5b`) and recording the video (`W6-4`)
are yours.

**4. I pushed a red gate once.** I ran `just check | grep passed`, saw
`All checks passed!` — which was `ruff check`'s output from the *first* of three
steps — and missed that formatting failed and the tests never ran. CI caught it
within a minute. Fixed, and written up
(`docs/journal/2026-08-21-1021-ci-red-after-W6-2.md`), because the lesson is
general: **check the exit code, not the output.**

## Two things I'd want a future run to know

**Every task in this run got done-criteria before it started, because none of them
had any.** Writing "done when: X, checked by Y" first is what turned three vague
lines into tasks that could be honestly closed — and twice it is what stopped me
closing one: W5-5's criteria said "not a Dockerfile that looks right", and W6-2's
demanded a page count from the finished file.

**The recurring defect in this codebase has one shape: something built, plausible,
and read by nothing.** It turned up as a task with no caller, a contrast test that
measured an empty string, a guard that could pass vacuously, a profile index that
silently fell back to "Anywhere", and an eval reader that dropped fields it had
not been told about. Every one was caught by asking the same question — *what
would prove this is actually doing something?* — and every one is now pinned by a
test that fails if it stops.
