# W3-3 — The questions panel, and the distinction that makes it not embarrassing

**Status:** DONE
**Files touched:** `whynot/questions.py` (new), `tests/test_questions.py` (new),
`whynot/api.py`, `tests/test_api.py`, `web/src/api.ts`, `web/src/TrialCard.tsx`,

## What I did

`docs/PLAN.md` says the thing a person actually walks away with is a list of
questions to ask the study coordinator. This task builds that list — the half of
it that does not need a model.

Each trial card can now end with two short sections:

> **ASK THE STUDY TEAM**
> *"Does this study enrol people who don't have the condition being studied —
> and would that apply to me?"*
> The registry record doesn't say either way.
> Registry says: accepts healthy volunteers: None
>
> **OR TELL US, AND WE CAN CHECK IT**
> Add your age and we can check this trial's age limits against it.

That is a real trial (`NCT06446232`, a Taiwanese influenza vaccine study), pulled
live, showing both kinds at once.

## The idea this task turns on

An `UNKNOWN` verdict has two completely different causes, and they need opposite
treatment:

- **The registry didn't say.** The healthy-volunteer field is blank; an age bound
  is written in a way nobody can parse. Nothing the person types fixes that — the
  answer exists only in the study team's protocol. *That* is a question for a
  coordinator.
- **The person didn't say.** They left the age box empty. The study team cannot
  answer that, and asking them to would be ridiculous — *"how old am I?"* is not
  a question for a research nurse.

Shipping those in one undifferentiated list would have taken the headline feature
of this project and made it look silly on the demo video. So the split lives in
the code, not in the interface's good intentions.

**And the split is by cause, not by field — which I got wrong first, and a test
caught.** My first version sorted by field name: age and sex are things a person
knows, so any unresolved age check went back to the person. Then the test for an
unreadable age bound failed. The age check goes `UNKNOWN` for *two* reasons — the
person left it blank, or the registry wrote `"between 18 and 65"` where a number
should be — and those are the same field with opposite owners. Sorting by field
would have told someone *"add your age and we can check it"* when they had
already given it and the record was the broken part.

So each field is now asked the direct question: **did the person leave this
blank?** If yes, it's theirs. If not, the gap is in the record, and that is a
question for the study team. There is a test named after exactly this
(`test_the_same_field_is_the_persons_to_answer_or_the_teams_depending_on_why`).

## Why I did it this way

**Anything unrecognised becomes a coordinator question by default.** Only `age`
and `sex` can ever be the person's to answer, and that set is pinned by a test so
widening it has to be deliberate. If somebody adds a fourth structured check to
`hardfilter.py` and forgets this module, its unknowns land in the study-team list.
That is the safe direction to fail: it produces a question the person didn't
strictly need, rather than silently swallowing one they did. A test walks all four
`UNKNOWN` situations the filters can produce and asserts each ends up in exactly
one of the two lists — never in neither.

**Every question carries the registry line that prompted it.** Rigor rule 2, on
the one output the person keeps. Somebody standing in a clinic with this printed
out can point at the line and say "this is why I'm asking".

**I changed a label from W2-3, and it was a defect rather than a preference.**
The check rows used to label every `UNKNOWN` "Ask the study team". Once this task
worked out that half the unknowns are the person's own, the card contradicted
itself — the row said ring a nurse, the panel underneath said add your age. The
label now reads "Not settled yet", which states the fact without claiming whose
move it is, and the panel below says whose move it is.

**I did not fold this into the criteria.** The eligibility criteria are shown on
the card, unread, with a note saying so. Most coordinator questions will
eventually come from *those* — a lab value, a scan, a date nobody typed in — and
that is W3-3b, blocked on the API key. The structure here treats the judge as
another source of unknowns feeding the same panel, so W3-3b is a merge rather
than a second parallel feature.
