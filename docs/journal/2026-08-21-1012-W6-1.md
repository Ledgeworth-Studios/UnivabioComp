# W6-1 — A README a judge can follow, proved by actually following it

**Status:** DONE
**Files touched:** `README.md`, `justfile`, `whynot/api.py`, `tests/test_api.py`,
`BACKLOG.md`

## What I did

Rewrote the README for the person it is actually for: a competition judge with
ten minutes, no context, and several other projects to get through.

It now opens with the one sentence that says why this exists — *everybody builds
clinical trial search, nobody builds trial rejection* — then gives four commands
from clone to running, then **six specific things to try and what to watch for in
each**. Then an honest table of what is built and what is not, then a guided tour
of where to look in the code.

**Then I cloned the repository into an empty directory and followed it literally,
command by command, using nothing from my own working copy.** That is the entire
value of this task, and it found two real defects that reading the file would
never have shown.

### Defect one: the second command didn't work

The README said:

```bash
just install
just dev
```

`just install` ran `uv sync --extra dev` and nothing else. `just dev` starts the
web interface. So a fresh clone got:

```
sh: vite: command not found
error: recipe `dev` failed with exit code 127
```

**Thirty seconds in, and the project appears broken.** `just install` now
installs both halves. Re-cloned, re-ran, and watched it come up: web on 5173, API
on 8000, six real trials from the live registry.

### Defect two: a 404 that explained nothing

Following the "run it as one server" path, `just serve` before `just web-check`
lands you on `/` and gets a bare **404**. Nothing tells you whether the project is
broken, the port is wrong, or you skipped a step. A judge with ten minutes does
not go hunting.

That request now answers with the two commands to run, and says the API itself is
working with links to `/docs` and `/api/health`. It returns 503, not 404 — the
resource isn't missing, the server just isn't ready to serve it yet. There is a
test.

### What the README claims, and how I know it is true

I checked every claim rather than trusting the file:

- Every path it names exists — all seventeen.
- The test counts are real: 179 Python, 69 frontend.
- It says "five decisions"; there are five files in `docs/decisions/`.
- `brew install uv just node` — all three are real formulae.
- The whole flow works from a fresh clone of the **pushed** repository, not my
  working copy.
- The specific things it tells a judge to try do what it says. Setting the age
  chip to 41 puts the paediatric MS trial **6th of 6** as *"This one is a
  conflict"*; setting it to 12 puts the same trial **1st of 6** as *"Nothing here
  rules you out"* — with all six still on screen, because nothing is ever hidden.
  The 91-site trial shows its Portland site 0.6 miles away.

## Why I did it this way

**The old README described the pipeline as though all of it existed** — free text
in, model judgement, ranked results — when two of those steps are not built and
are waiting on an API key. A judge who reads that, runs the demo, and finds the
criteria unjudged has been misled, and it is the kind of thing that costs more
credibility than the missing feature ever would. It is now a table with the
blocked rows marked and the single reason given, high on the page.

**Six things to try, with what to watch for.** "Search for a condition" invites a
judge to type something obscure, get three dull results and move on. Naming the
search *and* what makes it interesting — *this trial has 91 sites and the card
shows the one 0.6 miles away* — is the difference between a judge seeing the
point and a judge seeing a list.

**A "where to look in the code" section**, because the competition rules require
the entrant to walk judges through the code, and a judge who wants to look should
not have to guess which of eleven modules matters. It leads with the
architectural split the whole project turns on — structured fields in plain
Python, only the free text near a model.

**I did not add "known issues" as prose.** Both defects were fixed. A README that
documents its own broken first step is a README nobody finished.
