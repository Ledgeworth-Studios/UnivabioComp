# W1-5 — BLOCKED: the go/no-go spike cannot run without an API key

**Status:** BLOCKED
**Files touched:** `BACKLOG.md`, this journal entry. **No code was written.**

## What I did

I took the go/no-go task, found immediately that it cannot be done in this
environment, and stopped instead of building something that looks like progress.

W1-5 is the one task that could sink the project: can a model read real
eligibility prose and return coherent `MET` / `NOT_MET` / `UNKNOWN` verdicts? The
only way to answer that is to make real calls against real trials and read the
output. That needs an Anthropic API key, and there isn't one here.

I checked two ways rather than assuming:

- No `ANTHROPIC_API_KEY` (or any equivalent) exists in the environment the
  scheduled run sees. `ANTHROPIC_BASE_URL` is set to the ordinary public endpoint
  `https://api.anthropic.com`, so there is no local proxy standing in for a key.
- A direct call to that endpoint returns
  `HTTP 401 {"type":"authentication_error","message":"x-api-key header is required"}`.

So the block is real, not a configuration guess.

**To unblock:** put a key where the scheduled run can see it — `export
ANTHROPIC_API_KEY=...` in the shell profile the task inherits, or a `.env` file in
the repository root. `.env` and `.env.*` are already in `.gitignore` and must stay
uncommitted; the key must never appear in a commit, a fixture, or a journal entry.

## Why I did it this way

**I did not write the judge module anyway.** That was the tempting move: build the
prompt, the schema, the parsing, the tests-with-a-fake-client, and leave it for a
run that has a key. I decided against it, for the reason this task exists at all.

W1-5's done-criteria are almost entirely about the *output*, not the code — "run
it against five real trials by hand and paste the output into the journal", and
"if the verdicts are incoherent, say so plainly". The question being asked is
whether the model's judgement is trustworthy, and no amount of scaffolding built
blind answers it. Worse, scaffolding built blind actively harms the next run:
arriving to find a finished-looking `judge.py` invites "the code exists, just run
it" instead of the genuine evaluation the backlog asks for. The prompt and the
schema should be designed by whoever is watching real verdicts come back and can
iterate against them.

**I did not go looking for a credential elsewhere on the machine.** There are
stored credentials on this laptop belonging to other tools. Reaching into them to
make this project's API calls would work today and be wrong twice: it is not this
project's key to use, and it would produce a spike that runs for the agent and
fails for the human. The key has to come from the human.

**I marked it `BLOCKED` rather than putting it back to `READY`.** `READY` means a
run can pick it up and finish it. No run can finish this until a human acts, and
the next scheduled run would otherwise take it, rediscover the 401, and burn its
turn. The backlog entry now states the exact unblock step.
