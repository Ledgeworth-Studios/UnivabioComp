## What I did

This was the first build run — `docs/journal/` was empty, so nothing existed
except the plan, the backlog and the contract. I built the empty shell that every
later task drops code into.

Concretely, the project is now a normal Python package called `whynot` with four
things around it:

- **`pyproject.toml`** — the single file that says what the project is, what
  Python it needs (3.12), what it depends on (`httpx`, for talking to the trial
  registry later), and how the two quality tools are configured. The linter is
  `ruff` and the test runner is `pytest`. Both are listed as *dev* dependencies,
  so someone who only wants to run the app doesn't have to install them.
- **`justfile`** — a list of named commands. `just check` is the important one:
  it runs the linter, then the formatting check, then the tests, and stops at the
  first failure. The contract says nothing gets marked done until `just check`
  passes, so this file is what "done" actually means in practice.
- **`whynot/`** — the package. Right now it contains only a docstring naming the
  four modules the plan calls for (`registry`, `hardfilter`, `criteria`,
  `judge`) and a version number. It is a map of where the next tasks go.
- **`tests/`** — one test, which imports the package and asserts it has a
  version.

Everything runs through `uv`, a tool that builds the virtual environment from
`pyproject.toml` on demand. That means the setup instructions for a judge are
`just install` and then `just check` — there is no "remember to activate the
virtualenv" step to forget on camera.

`just check` exits 0. I ran it; the output is lint pass, format pass, 1 test
passed.

## Why I did it this way

**One real test instead of an empty suite.** The task said `just check` should
exit 0 "on an empty test suite". It won't — pytest exits with code 5 when it
collects no tests at all, so an empty suite would have made `just check` fail for
a reason that has nothing to do with code quality. Rather than paper over that
with a pytest flag, I wrote the smallest genuine test (the package imports and
has a version). It satisfies the spirit of the criterion and keeps the exit code
meaningful.

**A small, defensible lint rule set.** `ruff` can enable hundreds of rules. I
turned on five families — pycodestyle errors and warnings, pyflakes, import
ordering, pyupgrade, and bugbear — because each one is a rule the human entrant
can explain in a sentence if a judge asks why the code looks the way it does. A
maximal rule set would produce tidier code and unexplainable diffs.

**`uv` rather than pip and a hand-managed venv.** The alternative was a
`requirements.txt` and instructions to create a virtualenv. `uv` collapses that
to one command and produces `uv.lock`, which is committed, so the judge's clone
resolves to exactly the versions this was built against.

**Python 3.12, not 3.14.** The machine's default `python3` is 3.9.6, which is too
old for modern type syntax. 3.14 is installed but is new enough that a library
this project needs later could lag. 3.12 is already on the machine, needs no
download, and everything supports it. Pinned in `.python-version`.
