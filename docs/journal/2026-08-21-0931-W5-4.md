## What I did

`docs/PLAN.md` lists five rigor rules and says they are "testable requirements,
not aspirations". This task was meant to put them on screen. It turned into
something more useful, because I checked one of them before displaying it.

### The footer was lying

It said:

> Nothing you type here is stored or sent anywhere else.

**Both halves were false.**

*"Sent anywhere else"* — the condition and the coordinates go to
ClinicalTrials.gov on every single search. They have to; that is what searching a
registry means. The sentence denied the product's own central mechanism.

*"Stored"* — every request was given a `ResponseCache`, which wrote the registry's
response body and the time it arrived into `.registry-cache.db`. Nothing typed was
saved word-for-word, and it would have been easy to call that compliant. It isn't.
The stored answer to *"multiple sclerosis near Portland"* is a list of multiple
sclerosis trials in Portland, with a timestamp on it. Anyone reading that file
learns what was searched for. **There were fourteen such rows on this machine when
I looked.**

So the fix could not be a rewording. The code had to stop doing it.

**The response cache is now off unless somebody asks for it.** It was built for
reproducibility — a demo re-run, an eval re-run, the fixture recorder — and every
one of those has an operator in front of it rather than a patient. Set
`WHYNOT_CACHE_DB` and you get a cache; don't, and there is no file. The class is
untouched and the tools that need it still use it.

I verified this the only way that means anything: started the server in an empty
directory, ran real searches against the live registry, and looked.

```
--- files in the server's directory after live searches ---
.
..
```

There is also a test that runs a search in a temporary directory and fails if
anything appears.

### What the interface says now

Instead of one sentence that was wrong, three facts that are true, because they
are genuinely different from each other:

- Your condition and the place you picked **go to ClinicalTrials.gov** — that is
  the search.
- Your age, sex and healthy-volunteer answer **go no further than our server**.
  They are compared against what the registry sends back. There is a test that
  fails if any of them ever appears in the outbound request.
- **Nothing is written down**, and closing the page ends it.

### All five rules, and where each one is now visible

| Rule | Where you can see it |
|---|---|
| 1. Never assert eligibility | Every result set opens with *"You may qualify — only the study team can confirm."* It is on the printed sheet too. |
| 2. Every reason traceable | Every check prints *"Registry says: …"* beneath it, and the promise is stated up front so you know to expect it. |
| 3. No diagnosis, no treatment advice | **Was stated nowhere.** Now says it has no opinion about your health and is not a substitute for a doctor. |
| 4. Nothing stored server-side | The three facts above, and the code now matches them. |
| 5. Always link out | Every card carries the trial's status, the date its record was last updated, and a link — with the reason given: registry records change and ours is a copy made the moment you searched. |

They render as a plain list near the foot of the page, headed *"What this tool
will and won't do"*.

## Why I did it this way

**The wording lives in one module and is pinned by tests.** These sentences are
short and read like filler, which is exactly why they get softened during a
layout pass. `rigor.test.ts` asserts all five exist, that rule 1 uses the plan's
exact phrase, that rule 3 actually mentions diagnosis, treatment and a doctor,
that rule 4 admits data goes to ClinicalTrials.gov — and that the string
`"stored or sent anywhere else"` no longer appears anywhere in the interface.

**Not hidden behind a disclosure triangle.** A promise you have to click to read
is a promise arranged not to be read.

**The server owns the eligibility wording, not the page.** It was briefly in both
and read badly — the disclaimer said "only the study team can" twice in three
lines. Moving the canonical phrase into `whynot/api.py`'s `DISCLAIMER` fixes the
repetition and buys something better: **no client can render results without it**,
because it arrives in the same response as the results. A Python test pins the
exact sentence. The printed sheet keeps its own copy, because it is read away
from the page by somebody who never saw the screen.

   not delete it — the contract says not to remove things I did not create in this
   run — but **the human may want to**, and nothing depends on it.
2. **If caching is ever needed for load, it needs a new decision record**, not an
   environment variable set quietly. `docs/decisions/0005` says what such a
   decision would have to address: what is kept, for how long, and what the
   interface then has to stop claiming.
3. **The next `READY` task is W5-5** — deploy as a single container with FastAPI
   serving the built files. Note it interacts with this: production is same-origin
   by design, which is why the dev server proxies rather than the API allowing
   cross-origin requests.
4. **Live searches now always hit ClinicalTrials.gov**, roughly 0.3s per the
   plan's own measurement. If a demo feels sluggish, that is the cost of rule 4
   and it is the right way round.
5. **174 Python tests, 69 frontend tests**, both gates green.
