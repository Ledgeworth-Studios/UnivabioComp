# Correction — W6-2 was marked DONE while the gate was red

**Status:** DONE (fixed and green)
**Files touched:** `tools/build_one_pager.py` (formatting), `docs/one-pager.pdf`

## What happened

I pushed W6-2 with a failing `just check`. CI caught it; I had not.

`ruff format` rejected `tools/build_one_pager.py` after I hand-edited the type
sizes into multi-line argument lists it wanted formatted differently. That is
trivial. **How I missed it is not.**

I ran the gate like this:

```bash
just check 2>&1 | grep passed
```

and saw `All checks passed!` — which is **`ruff check`'s** output, printed by the
first step of a three-step recipe. `ruff format --check` then failed, the recipe
aborted, and `pytest` never ran at all. My filter matched a success line from a
step that had succeeded and reported green for a run that had failed.

The tell was there and I read past it: the output had no `179 passed` line in it.
A passing gate always prints one.

## The lesson, which is not about formatting

**Check the exit code, not the output.** `just check; echo $?` cannot lie.
Grepping the output of a multi-step command for a hopeful word can, and will,
whenever an early step prints something that matches and a later step fails.

I had been doing this for most of this run. It happened to be harmless every
other time, because nothing failed. That is not the same as being safe.

There is a second lesson, and it is the reason CI exists: **the remote gate
caught something the local one was being asked the wrong way.** `docs/decisions/`
records the reasoning for CI being the same command as the local gate — this is
the first time the arrangement has actually paid.

## What the next run should know

- **Run `just check` and `just web-check` plainly, and read the exit code.** If
  you must filter, filter *and* check the status: `just check > /tmp/out; echo $?`.
- A green `just check` prints `N passed` from pytest. If that line is missing, the
  suite did not run, whatever else the output says.
- W6-2's work itself was fine — the one-pager, the renderer and the page guard
  were all done and verified. It was the gate that was not checked properly, and
  it is green now.
