# W1-3 — Age, sex and healthy-volunteer filters, decided in plain Python

**Status:** DONE
**Files touched:** `whynot/hardfilter.py`, `whynot/profile.py`,
`whynot/__init__.py`, `tools/record_fixtures.py`, `tests/test_hardfilter.py`,
`tests/fixtures/registry/age_and_sex_shapes.json`, `BACKLOG.md`

## What I did

The registry hands back two very different kinds of information about who a
trial will enrol. There is a **free-text blob** of criteria written for doctors
("adequate hepatic function", "no prior exposure to..."), and there are four
**structured fields**: minimum age, maximum age, sex, and whether the trial takes
healthy volunteers.

This task handles the structured four. They are just numbers and labels, so the
answer is arithmetic. No model is called, nothing costs money, and running it
twice gives the same answer twice. That was a deliberate architectural choice
made in `docs/PLAN.md` before any code existed, and this is the module that
honours it.

**`whynot/hardfilter.py`** answers three questions about one trial and one
person, and each answer is one of three values — `MET`, `NOT_MET`, `UNKNOWN` —
plus a plain-English sentence and the registry text it came from.

Real output, for a 34-year-old man:

```
NCT07000786 RULED OUT
    MET      This trial enrols ages 18 Years to 56 Years, which includes 34 years old.
    NOT_MET  This trial enrols female participants only.
    MET      This trial accepts healthy volunteers.
```

And for someone who told us nothing about themselves:

```
    UNKNOWN  This trial enrols ages 18 Years to 56 Years. You didn't tell us your age.
    UNKNOWN  This trial enrols female participants only, and we could not tell
             which applies to you. Ask the study team.
    MET      This trial accepts healthy volunteers.
```

That second block is the whole product in miniature. Saying nothing about
yourself never rules you out of anything — it turns into a question instead.
There is a test (`test_an_empty_profile_produces_questions_and_no_rejections`)
that runs an entirely blank profile against all eleven real trials and asserts
that not one of them rejects the person.

### The age strings are worse than they look

The obvious assumption is that ages come back as `"18 Years"`. I checked the live
registry rather than assuming, and they do not. Real bounds found on real
recruiting trials include:

| Registry text | Trial |
|---|---|
| `6 Hours` – `72 Hours` | NCT02210026 |
| `3 Days` – `5 Days` | NCT00113191 |
| `5 Weeks` – `24 Months` | NCT06737159 |
| `24 Months` and older | NCT00157079 |
| up to `2 Years`, no minimum | NCT01271491 |
| no bounds at all | NCT02138032 |
| `18 Years` – `120 Years` | NCT06096870 |

So a trial can express its lower bound in weeks and its upper bound in months,
and comparing them requires putting both on one scale. `parse_age_to_years`
converts hours, days, weeks, months and years into years, and everything is
compared as years thereafter. All eleven of those trials are recorded as a real
fixture (`age_and_sex_shapes.json`), each one listed in
`tools/record_fixtures.py` with a comment naming the shape it exists to cover, so
nobody later deletes one thinking it's a duplicate.

**`whynot/profile.py`** is new: a small frozen dataclass holding what the user
told us — age, sex, whether they are volunteering as a healthy person, and their
conditions. Every field is optional. Filling it in from free text is W2-1's job;
this task just needed something to compare trials against.

55 tests pass.

## Why I did it this way

**An unreadable age raises, an absent age returns None.** These are different
situations and conflating them is how a parser bug becomes a wrong medical-ish
answer. A missing `maximumAge` is completely normal — most adult trials have no
upper limit — and returns `None`. But a `minimumAge` that exists and doesn't
parse means the registry did something I've never seen, and quietly treating that
as "no limit" would silently widen every trial's eligibility. It raises
`UnparseableAge`, and the caller catches it and returns `UNKNOWN` — "ask the
study team" — rather than either excluding or admitting the person.

**`UNKNOWN` on an unrecognised sex, not a guess.** The registry only records
`ALL`, `FEMALE` or `MALE`. The profile takes whatever the user typed. I mapped a
short, explicit list of words (`f`, `female`, `woman`, `m`, `male`, `man`) and
everything else — including `intersex`, which has a test — comes back `UNKNOWN`
with a question to ask the coordinator. The alternative was to try harder to
interpret how people describe themselves, which is exactly the kind of guessing
this project exists not to do.

**`healthyVolunteers: false` is read narrowly.** It is tempting to read that
field as "you must have the condition", and then reject anyone who hasn't said
they have it. That would be wrong twice over: the field only says the study isn't
*recruiting* healthy volunteers, and the real diagnosis requirements are in the
free text where the model reads them in W1-5. So `false` only rules out someone
who has explicitly told us they are volunteering while healthy. Everyone else
passes this check and gets judged on the criteria text.

**Bounds are inclusive.** Someone who is exactly 18 qualifies for an "18 Years
and older" trial, and someone who is exactly 18 qualifies for a "up to 18 Years"
trial. That is how the registry is written and how a coordinator would read it.
There is a test pinning both ends.

**A new module rather than putting `PatientProfile` in `hardfilter.py`.** The
backlog named only `hardfilter.py`, but the judge (W1-5) and the demo (W1-6) both
need a profile too, and `from whynot.hardfilter import PatientProfile` would read
like nonsense to anyone opening the code cold. `whynot/profile.py` is thirty
lines and I updated the package docstring's module map to list it.

## What the next run should know

- **W1-4 (criteria splitter) is next, and the fixtures you need already exist.**
  `search_ms_portland.json` has five real criteria blobs and
  `age_and_sex_shapes.json` has eleven more, spanning trials registered from 2001
  to 2026 — which matters, because old records are formatted differently from
  new ones. Look at `NCT00113191` and `NCT00132080` (2004–2005 registrations)
  before assuming every blob has tidy `Inclusion Criteria:` headers.
- **I added D-2 to the backlog, and it is a real correctness hazard, not
  bookkeeping.** `NCT01066728` has bounds `27 Weeks`–`32 Weeks`. Those are
  *gestational* ages — how far along the pregnancy was — not how old the baby is.
  The registry has no field that distinguishes gestational from postnatal, so the
  current code converts them like any other age. For a neonate that could produce
  `NOT_MET` where the truth is `UNKNOWN`, which `docs/PLAN.md` names as the most
  dangerous error this system can make. It doesn't affect the demo (adult disease
  area) but it must not vanish quietly.
- **Two rigor rules now have tests, not just intentions.** Rule 1 (never assert
  eligibility) is enforced by the wording — nothing in this module says "you are
  eligible"; a `MET` says the field "does not rule you out". Rule 2 (every reason
  is traceable) is enforced by `HardCheck.source`, and a test asserts every check
  carries one.
- The awkward-sounding line "This trial does not accept healthy volunteers, which
  does not rule you out" is deliberate and correct — it is telling the user that
  a field which *looks* like a barrier isn't one for them. If a later run wants
  to reword it, keep the meaning.
